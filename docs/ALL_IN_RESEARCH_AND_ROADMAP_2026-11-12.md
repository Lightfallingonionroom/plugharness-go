# PlugHarness-Go All-in 研究结论与分阶段路线图

> 状态：研究与规划稿，2026-11-12。
>
> 本文不是 Flash 实施任务书，也不是代码变更说明。它先固定事实、范围、优先级、依赖和验收闸门。用户已明确选择 All in，表示候选能力全部进入长期路线图；不表示一次构建全部完成。
>
> 研究范围：当前 PlugHarness-Go 源码与文档；Operit `AAswordman/Operit` `16cffb98f52a11dc77bd0a789ffa0b01ed398ee4`（2026-11-08，LGPL-3.0）；Mika `wangzan101/Mika` `0c9e27d1ee3d`（2026-11-11，Apache-2.0）；mobile-mcp `mobile-next/mobile-mcp` `ad3b42336d89`（2026-11-11，Apache-2.0）；Angel `CurrenlyDying/angel-android` `de802225c6bf`（2026-11-08，Unlicense）；OpenMinis `OpenMinis/OpenMinis` 当前 `main`（2026-11-10，GPL-3.0）。参考项目只作为功能与架构证据，禁止直接复制 GPL/LGPL 代码到本项目，除非另行完成许可审查。

## 1. 结论先行

### 1.1 真正的产品缺口

PlugHarness-Go 不是功能数量少，而是缺少四个“系统层”能力：

1. **任务操作系统**：统一管理多个对话、手机任务、后台任务、定时任务、等待确认、资源占用和恢复。
2. **配置与数据操作系统**：模型路由、凭据引用、用量、配置快照、会话导出、主机数据备份需要统一边界。
3. **可观察性**：用户需要知道 Agent 做了什么、为什么等待、用了多少、结果是否已确认，而不是只看到聊天文本。
4. **跨界面入口**：App 内、后台通知、悬浮胶囊、电脑 CLI/MCP 等入口需要共用任务身份和所有权。

### 1.2 本次 UI 方向已确认

- 聊天标题上方单独一行，居中放快捷入口。
- 收起为三个横向圆点，展开为三个横向胶囊：终端、团队、文件。
- 替换原来分散的终端按钮和团队入口；以后再做快捷项自定义。
- 新对话页三个快捷按钮保留但置灰，不自动创建会话。
- 默认颜色按用户要求走 ChatGPT 式中性黑白灰；彩色配色保留在次级选项。**2026-11-12 开工后复核纠正**：`DshPalette` 的中性色常量是 `openai/apps-sdk-ui --gray-*` 源码实测令牌，被 `app/test/theme/official_palette_test.dart` 精确钉死；用户截图是 JPEG，量出的 `#FBFBFB`/`#F5F5F5` 与官方令牌差 2~4/255，属于压缩/渲染偏差，不能作为把官方令牌改成近似值的依据。同时 `scheme.surface` 与 `ChatGptShellColors.page` 已由该测试断言同源，「两套色板不统一」是修复前的旧状态。因此本轮颜色工作的真实缺口不是改常量，而是让 `ChatGptShellColors` 里仍硬编码的 composer/边框/行态/文字跟随 `NeutralTones.forAccent(accent)`，以及修正设置页色点显示。
- 权限在控制菜单内直接切换，不再先进入权限卡片；不做二次确认。后端仍是权威，失败必须回显失败，不得乐观宣称成功。
- 模型配置采用按提供商预设模型和 API 地址、可手动覆盖且不被自动覆盖的方向。
- 备份恢复纳入 All-in 第一阶段地基。
- Token 统计纳入 All-in 路线。此前“暂不纳入本轮”的说法已被 All-in 覆盖。

## 2. 当前能力校正

### 2.1 已经存在，不应重做

- 终端：多标签、快捷键、工作区绑定，代码在 `app/lib/ui/terminal/` 和 `app/lib/state/terminal_state.dart`。
- 工作区文件：目录浏览、文件预览、产物预览、上传/下载路径，代码在 `app/lib/ui/workspace/`、`app/lib/ui/files/` 和相关状态。
- 团队与子代理：`TeamPage`、`HeaderAgentsKey`、团队任务/成员/消息，代码在 `app/lib/ui/agents/`。
- 自动化任务：`SchedulesPage`、任务编辑/历史/立即运行、主机协议。
- 后台任务：`JobsPage`、跟随输出、停止/取消、状态展示。
- 模型渠道：读取主机 `pi-ai` provider profile，编辑 base URL、协议、模型、凭据引用、模型上下文/输出信息，发现模型时已有根地址 `/v1` 兜底逻辑。
- 思考规则：`thinking_rules_state.dart` 已有 provider/model 通配、前缀匹配、规则排序、启停、always/manual、兜底档位，发消息前复用 `ModelSelection.reasoningEffort`。
- 会话用量：`SessionUsage` 已读取 `tokenUsage`、缓存读写、上下文压力/分解、轮数、LLM/工具耗时，并有会话级成本估算与余额页。它不是跨会话历史统计数据库。
- 手机后台屏：原生 `VirtualDisplay`、背景任务资源槽位、并发上限、任务等待、预览、资源清理与恢复已经存在。相关代码在 `app/android/app/src/main/kotlin/.../phone/background/`、`PhoneTaskSessions.kt`、`app/lib/phone/`。
- 手机任务并发：已有 native capacity、background slot、等待应用/屏幕/资源的状态；缺少的是面向用户的统一任务中心、跨任务互斥可视化和更完整的长期任务调度。
- 分享/导出：已有会话日志 ZIP、profile/plugin/skill/config 分享码、对话回放/分享设计；这些不是完整的主机数据备份恢复。
- 插件市场、插件安装队列、插件设置、技能、MCP/远程主机基础、远程 SSH/WebRTC/Relay、诊断包、安全模式、LKG 恢复已存在不同程度实现。

### 2.2 部分存在，需要升级

| 用量 | 单会话实时投影、缓存比例、上下文、估算成本 | 跨会话持久化、按日期/provider/model 聚合、未知值计数、真实/估算/未计价分层、导出 |
| 备份 | 运行环境保留、诊断包、LKG、分享码、会话日志导出 | App 设置快照、主机 profile/技能/插件可选备份、远程主机范围、会话与附件恢复、版本/冲突/还原点 |

| 插件/MCP | DSH 插件市场、原生接缝、MCP 连接基础 | 统一扩展中心、配置/凭据范围、健康检查、权限与生命周期统一视图 |

### 2.3 确实缺失或暂未形成产品能力

- 跨会话 Token 用量历史数据库与统计页。
- 完整的可恢复备份系统，尤其是远程主机上的 DSH profile/对话/技能/插件配置边界。
- 统一任务中心，聚合聊天回合、手机任务、后台 job、schedule、团队任务。
- Mika 类“App/网站使用知识库”机制。
- Mika 类电脑端 CLI/Skill/MCP 派任务与任务台。
- OpenMinis 类全量 Agent 面板/手机设备能力整合，需要研究后再决定是否纳入实现。
- Operit 类本地 GGUF/MNN 推理，不是 UI 级功能，涉及磁盘、内存、模型下载、工具协议和稳定性。
- Operit 类可视化工作流编排，不是普通设置页，需独立数据模型、执行器和恢复协议。
- Operit 类角色卡/多角色群聊/图谱记忆扩展，PlugHarness 现有账户/记忆路线可吸收部分，但不能直接照抄 Operit 数据模型。

## 3. All-in 功能池排序

排序标准：日用收益 35%，对现有路线复用 25%，安全/可靠性收益 20%，实施风险倒数 20%。A 不是“马上全部做”，而是优先级。

### A0，地基闸门，必须先做

1. **统一任务身份与任务中心模型**
   - taskId、sessionId、hostId、accountId、workspaceId、task kind、owner、state、progress、waiting reason、resource leases、created/updated/ended、recovery state。
   - 复用现有 session/job/phone/schedule/team 数据，不造第二套 Agent loop。
   - 所有后台任务必须能说明“属于谁、在哪跑、现在为什么停、是否可恢复”。

2. **快捷入口折叠菜单**
   - 标题上方居中三点/三胶囊，终端、团队、文件。
   - 旧终端按钮和旧团队图标移除，组件支持新对话 disabled。
   - 这是后续任务中心的入口，不把路由逻辑散在多个按钮。

3. **主题和颜色统一**
   - 默认 graphite 中性色壳层。
   - 首屏彩色预设降为次级选择，官方十色保留但不抢默认。
   - 明确 surface/page/sidebar/composer/action/userBubble 的角色，不把 provider seed 当全局壳层颜色。
   - 浅色/深色、无玻璃降级、对比度和真机截图必须一起验证。

4. **权限直接切换**
   - 控制菜单直接列出实际预设。
   - 请求主机 `setPermissionPreset`，状态以回读为准。
   - 无会话时展示 disabled，不能偷偷创建会话。
   - 不做额外二次确认，但保留主机/引擎实际拒绝、断线、权限不可用的错误态。

5. **模型配置基础层**
   - ProviderPreset 数据模型：provider id、协议、默认 endpoint、endpoint options、默认模型、是否需要 key、模型发现方式。
   - 自动补全只填空字段；用户编辑过的 endpoint/model/key 设 dirty 标记，切换预设不能覆盖。
   - 保存前连接测试、发现模型、诊断结果和凭据引用分开显示。

### A1，直接提升日用效率

6. **模型身份归一与路由组**
   - 原始 provider/model identity 不丢；display identity 可归一。
   - 同一逻辑模型配置多个 route，支持顺序故障转移、冷却、最近错误、手动锁定。
   - 每次切换必须显示当前 route 和原因，不能静默换模型。

7. **跨会话 Token 用量统计**
   - 先定义数据事实：本地实时 projection、主机 event/history、provider billing response 三类来源。
   - 记录 request/session/host/account/provider/model/route/time/input/cache-read/cache-write/output/reasoning/knownness。
   - unknown 不能当 0；估算成本必须标“估算”，没有价格就显示未计价。
   - 页面：今日/7日/30日/自定义、按模型/provider、缓存命中、总请求、未知计数、导出 CSV/JSON。

8. **完整备份恢复**
   - 先拆四个范围：App 本地配置、运行环境用户数据、主机 DSH profile、聊天/附件/工作区。
   - 默认不备份 API key/token/cookie/登录态；可备份 credential reference，不备份 secret value。
   - 本机可做原子快照；远程只能通过明确支持的主机接口做导出/恢复，不能假设 App 能读远程数据库。
   - 每份备份有 schema version、source host/account、createdAt、manifest、sha256、大小和敏感内容标记。
   - 恢复先预览差异，再按范围勾选；先写 restore point，失败可回滚；跨版本拒绝或迁移，不静默覆盖。

9. **统一任务中心和任务台**
   - “正在运行 / 等待我 / 等资源 / 已完成 / 失败 / 已取消 / 未确认”统一状态。
   - 支持查看进度、跳到来源会话、停止、暂停/恢复（只有后端支持时出现）、重试、确认结果。
   - 手机任务显示 background slot、占用 App、等待原因；schedule 显示下一次运行；job 显示日志；团队显示成员任务。

10. **后台任务 UX 补强**
    - 利用现有后台屏和 `PhoneTaskSessions`，不重写 VirtualDisplay。
    - 增加资源冲突解释、App 互斥、超时、死锁检测、清理未确认恢复、任务结果与通知关联。
    - 先支持任务队列和资源等待，再评估 Mika 式“同 App 排队”。

### A2，可信度和自动化

11. **App/网站知识库**
    - 每个 package/domain 一套版本化 Markdown/结构化知识。
    - 先是只读提示，Agent 按需检索；来源、版本、更新时间、适用范围可见。
    - 用户可覆盖、禁用、导出；不能让第三方知识直接获得权限。
    - 手机路线回放和知识建议必须分开，知识不能替代实际屏幕验证。

12. **条件定时任务增强**
    - 在现有 schedules 上增加条件、比较上次值、去重窗口、每日最多提醒次数、失败策略、预览未来触发点。
    - 任务编辑权限与普通聊天权限分开，沿用已有主机授权契约。

13. **过程记录和来源标注**
    - 回合/工具已有 trace 统一做“来源、输入、输出、耗时、token、脱敏状态”视图。
    - 浏览器来源、文件来源、截图/OCR 来源分别显示；不伪造“已验证”。

14. **风险模式**
    - 在现有权限系统上增加“询问/自主”作为任务级策略，不替换 capability/preset。
    - 默认询问高风险/花钱/登录/验证码/付款，普通操作可按用户配置自动执行。
    - 定时任务无人值守时，高风险动作必须明确停止并记录，不等待无限期。

15. **悬浮任务胶囊和跨 App 入口**
    - 复用已有通知/宠物 overlay 能力，先显示任务状态、确认、结果和停止。
    - 双击当前屏、悬浮语音、跨 App 插话要单独做权限与隐私设计，默认关闭。

### A3，扩展生态和跨设备

16. **电脑端 CLI / Skill / MCP 任务入口**
    - 复用同一个 task identity 和 outbox，不创建第二个远程 Agent loop。
    - USB/ADB 优先，Wi-Fi/VPN 明确绑定、令牌、TLS/网络范围、历史查看开关。
    - 电脑端只能派任务和看结果，高风险确认仍回手机。

17. **统一扩展中心**
    - 合并插件、ToolPkg、Skills、MCP 的发现、安装、更新、禁用、权限、诊断。
    - 使用现有 plugin marketplace/compatibility、MCP 配置和 skills，不复制三份安装系统。
    - 每个扩展声明能力、来源、版本、许可、所需凭据、网络/文件/手机权限。

18. **模型本地推理**
    - GGUF/llama.cpp/MNN 只先做技术可行性和磁盘/内存预算，不直接承诺集成。
    - 需要模型下载、校验、取消/恢复、内存占用、工具调用兼容、上下文、卸载和崩溃恢复。

19. **可视化工作流**
    - 先定义 DAG/触发器/条件/数据映射/重试/取消/幂等/日志 schema。
    - 复用 schedule/job/task center；不让工作流自己偷偷起另一套 Agent loop。

20. **角色卡、群聊、图谱记忆扩展**
    - 与已确认的场景账户、角色卡、记忆隔离设计对齐。
    - 角色的模型、权限、skills、MCP、memory 必须经过账户授权过滤。
    - 不把 Operit 的“角色独立能力”直接复制成绕过账户权限的快捷通道。

21. **浏览器 Agent 与用户脚本**
    - 先沿现有浏览器边界重新评估。当前内置浏览器探针已知不能截图，CSP 严格页面也受限，因此不能把 Operit 的完整浏览器 Agent 当成可直接移植功能。
    - 优先做插件/外部浏览器路线，明确支持矩阵，不承诺通用网页自动化。

22. **移动端高级能力**
    - OCR/视觉找控件、录屏、崩溃报告、MCP 设备控制可吸收 mobile-mcp 的结构化输出理念。
    - 先使用无障碍树，截图/坐标作为降级；所有敏感操作保留用户接管。

### A4，低优先级但纳入候选

23. 语音连续对话、唤醒词、自动朗读、TTS 队列。
24. Live2D/桌宠/伙伴小屋扩展。
25. 多角色群聊和 DS Bot 深度联动。
26. 自定义主题编辑、字体、背景、Markdown、布局。
27. 统一市场中的提示词、标签、Artifact、项目发布。
28. 屏幕录制、Logcat、SQLite viewer、APKTool、HTML 打包等开发工具面板。
29. 更完整的分享码/对话回放/跨端加密分享。

## 4. 参考项目如何取舍

### Operit

可学原理：

- Provider 配置表 + 默认 endpoint/model + endpoint options。
- 每模型完整配置对象，参数开关与自定义参数分离。
- 思考规则按 provider/model/endpoint 匹配，首条规则优先，动作映射到请求路径。
- TokenUsage 本地事实表，未知 token/未知价格单独计数，按日期、provider、model、缓存拆分。
- 数据库 WAL checkpoint 后备份，自动备份/手动备份/保留份数。
- 文件管理器的工具栏、搜索、显示模式、上下文菜单。
- 工具、ToolPkg、MCP、Skills、工作流统一生态概念。

不直接复制：

- LGPL 代码。
- 角色卡/多角色的原始数据模型。
- 默认把大量 Android 工具都塞进权限系统的做法。
- 依赖本地 Room 数据库的备份假设，PlugHarness 的聊天主数据可能在 DSH 主机。

### Mika

可学原理：

- 后台屏与主屏分离，预览只读、任务可在后台继续。
- 同一个 App 的任务互斥，明确显示等待原因。
- 询问/自主是任务级风险策略，登录、验证码、付款始终交给人。
- App/网站知识作为版本化文本技能，按需读取，不自动获得权限。
- 悬浮任务胶囊、双击当前屏、跨 App 插话。
- CLI/Skill/MCP 共用一个手机任务服务，电脑端只负责派任务和观察。
- 条件定时任务以“和上次比较”为一等能力。

不直接复制：

## 6. 统一验证原则

### 所有功能都必须回答

- 数据事实来自哪里？本机、主机、provider，还是估算？
- 失败之后是否可重试、可恢复、可解释？
- 当前任务是否仍属于原账户、主机、会话和工作区？
- 是否会把凭据、路径、截图、聊天内容泄露到日志/备份/电脑端？
- 是否与已有 DSH Web API、远程主机、插件、MCP 向后兼容？

### 必须有的证据

- 纯 Dart/Kotlin 单元测试：schema、匹配、优先级、脱敏、冲突、状态迁移。
- Flutter widget/golden：空、加载、失败、离线、无权限、大字号、深浅色。
- 主机协议夹具：成功、拒绝、断线、旧版本、不支持。
- 真机 Android 16 arm64：后台屏、Shizuku/ADB、通知、悬浮、安装更新、运行环境、磁盘预算。
- 远程主机：SSH/Relay/WebRTC、无工作区、无写权限、断线恢复。
- 安全测试：备份/导入不带 secret，路径穿越拒绝，来源和许可显示，权限不因标签自动提升。
- 性能基线：冷启动、后台屏创建/清理、任务中心刷新、模型目录刷新、统计查询和备份耗时/空间。

## 7. All-in 不等于一次交付

建议实施窗口：

- **A 地基与视觉校正**：快捷入口、颜色、权限直切、任务身份、Provider preset 初版。
- **B 配置与可观察性**：模型路由、思考规则、Token 历史、任务中心、来源/过程视图。
- **C 数据安全**：本机/主机备份恢复、还原点、敏感字段、冲突与版本迁移。
- **D 手机任务增强**：后台任务队列、互斥、悬浮胶囊、知识库、条件自动化。
- **E 跨设备与生态**：电脑 CLI/MCP、统一扩展中心、插件/MCP/技能诊断。
- **F 高风险评估**：本地模型、可视化工作流、浏览器 Agent、角色群聊、语音/伙伴扩展。

每个窗口完成后才进入下一个窗口；每个窗口都需要 CI、真机和证据报告。Flash 不得把所有窗口压成一个提交或一个“看起来能跑”的 APK。

## 8. 当前需要用户选择的不是“做不做”，而是交付批次

All-in 的功能池已经全部保留。下一步只需决定：

- 第一批是否包含 Token 历史统计（建议包含，因为模型配置和价格数据共用地基）。
- 第一批备份是否只做 App 本地设置/配置快照，还是同时做本机 DSH 主机的 profile/skills/plugins；远程主机备份建议第二批。
- 手机任务增强是否先做任务中心和互斥 UX，还是先做悬浮胶囊；建议先任务中心。
- 电脑 CLI/MCP 是否作为独立批次，不与手机 UI 同时改动；建议独立。
