## A. 顶栏终端入口位置 —— 已满足（已有会话页），新对话页待定

**核实结果**：`_HeaderRow.place(trailing, width - fresh.width - trailing.width)`
（`chat_header.dart`）—— 终端键（`WorkProgressKey`）**就在「新建聊天」左边**，
`trailing` 排在 `fresh` 之前。已有会话页完全符合评论要求。

**新对话页没有终端键**：`chat_screen.dart:1837` 是
`trailing: sessionId == null ? null : WorkProgressKey(sessionId: sessionId)`。
原因是 `TerminalPage.route(String sessionId)` 与
`terminalWorkspaceProvider(widget.sessionId)` **强依赖会话 id**，
无会话时硬加会崩。

**结论**：这是产品决策点（要不要给终端页做「无会话」模式），未擅自改。

## B. 权限/插件胶囊收进齿轮 —— 已落地（`ea7f21b3`）

**改动**：
1. `ComposerControlsKey`（`model_sheet.dart`）从 `StatelessWidget` 改为
   `ConsumerStatefulWidget`，内部用 **`MenuAnchor`** —— 弹层从「占满底部的
   `showAppSheet`」改成**锚定齿轮的紧凑菜单**（Material 自带边缘避让、键盘安全）。
2. 菜单只有三个一级项（评论 B 明确要求，**不含计划模式**）：
   - 权限 → `showPermissionSheet`（`SessionPermissionPage`）
   - **插件 → `PluginsScreen`**（新增，此前控制面板没有插件入口）
   - 模型 → `showModelSheet`（保留）
   复用 `AppMenuPanel` / `AppMenuItem`（官方规格：圆角 16、项高 32、✓ 选中）。
3. **移除输入框上方的独立权限胶囊**：`_composerPills` 只留生成模式胶囊；
   权限只在**运行中**的窄带上出现（`_stripRisk`）——那是"正在发生的事"，
   不是"这条消息用什么条件"，符合评论的意图。
4. 新增 l10n `chatComposerPlugins`（中英 + gen 同步）。

**测试**：`plus_panel_test` 的 `permission pill` 组改为
`permission entry (齿轮菜单)`（测新入口可点开）；`generate_mode_test`
的「权限胶囊 + 生成胶囊并排」改为「生成胶囊独占一行」；
`plus_panel_test` 的权限胶囊 golden 改为齿轮菜单 golden。

**未确认**：评论提到的「插件胶囊」在代码里**找不到对应的独立组件**
（`chat_screen` 只有权限/自动允许/生成模式三种胶囊，`NativeComposerBar`
是插件动态 UI 的容器而非"插件"胶囊）。可能是旧 APK 的遗留。

## C. 推理强度仪表可点 —— 已修复（`356f266b`）

**根因**：`ComposerEffortKey.open()` 里
`if (efforts.length < 2 || effective == null) return;` —— 目录未到 / 模型只有
1 档时**静默 return**，用户点了毫无反应（评论称"摆设"）。

**修法**：两种情况都给回应。有 ≥2 档 → 打开档位选择；否则 → 弹
`showEffortUnavailableSheet`，讲清是「还没拿到模型列表」还是
「这个模型只有一个档位」。新增枚举 `EffortUnavailableReason` 与两条 l10n。

**未做**（评论 C 还要求）：`widget/state` 测试（按钮可点击、弹层打开、
选项动态匹配模型、选择后 `setModel` 被调用、切换模型时更新、无 efforts 时降级）。
本机跑不了 `flutter test`，未猜着写。
